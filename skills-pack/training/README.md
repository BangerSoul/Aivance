# Skills Training Corpus (JSONL)

Training-ready exports of every skill in the pack — generated by
`skills-pack/tools/export_training_jsonl.py` (stdlib-only, re-runnable,
CI-safe: it self-verifies line counts and schema before exiting non-zero).

## Files

| File | Lines | Format | Best for |
|------|-------|--------|----------|
| `skills_corpus.jsonl` | 41 | Record objects | Prompt libraries, RAG indexes, structured knowledge bases |
| `skills_chat.jsonl` | 41 | Chat messages | Direct instruction fine-tuning (SFT) |

Both are strict JSON Lines: one JSON object per line, UTF-8, no trailing
commas. Every line carries `id` (the stable skill slug, e.g. the directory
name it loads under) + `name` (the human-readable frontmatter title — differs
from `id` for UESF core skills, e.g. `uesf-co-planning` → "Planning-First
Execution") + `tier` (uesf-core / community / original / learned) so you can
filter the corpus by provenance.

### Record format (`skills_corpus.jsonl`)

```json
{
  "id": "coding-discipline",
  "name": "coding-discipline",
  "tier": "learned",
  "path": "learned/coding-discipline/SKILL.md",
  "trigger": "Behavioral guardrails that reduce the most common agent coding mistakes…",
  "task": "Following the coding-discipline skill, behavioral guardrails that reduce…",
  "system": "You are the 'coding-discipline' skill module of an engineering agent.\nWhen to use it: …",
  "instructions": "# Coding Discipline\n\nBehavioral guidelines to reduce…",
  "source": "multica-ai/andrej-karpathy-skills mattpocock/skills"
}
```

- `system` — the skill's frontmatter (`name` + `description`) rendered as a
  system prompt: identity + when-to-use clause.
- `instructions` — the full SKILL.md body (frontmatter stripped).
- `trigger` — the applicability clause (WHEN to invoke).
- `task` — an imperative framing (WHAT to do) derived from the description,
  kept distinct from the trigger for clean input/behavior pairing.

### Chat format (`skills_chat.jsonl`)

```json
{
  "messages": [
    { "role": "system",    "content": "You are the '…' skill module…" },
    { "role": "user",      "content": "Apply the … skill: …" },
    { "role": "assistant", "content": "<full SKILL.md body>" }
  ],
  "id": "coding-discipline",
  "skill": "coding-discipline",
  "tier": "learned"
}
```

Drops straight into Hugging Face `datasets` / Axolotl / LLaMA-Factory / etc.
for SFT: load, `shuffle`, train.

> **Caveat — this is a content-mapping corpus, not a task-execution corpus.**
> The assistant turn is the full SKILL.md body, so the model learns "when this
> trigger appears, reproduce this skill text." That is the right signal for
> teaching a model to *emit a skill's instructions*, but it is not a substitute
> for real task-execution samples. For production SFT, use
> `skills_corpus.jsonl` as the knowledge base and format few-shot
> task-execution examples (real issue → resolved code) around each skill's
> trigger; keep `skills_chat.jsonl` as the grounding/priming corpus.

## Using it to fine-tune another model

1. **Filter by tier** — for the cleanest, license-clean training signal prefer
   the `learned` tier (16 original syntheses). Community skills are third-party
   MIT/Apache licensed; check each source before shipping a derivative model.
2. **Downsample the chat format** — one line per skill; if your run needs more
   samples, duplicate lines with varied `task` phrasings or shuffle heavily.
3. **Keep `system` + `instructions` coupled** — the model learns "when this
   description matches, emit this behavior," which is exactly the
   skill-invocation mapping the pack encodes.

## Regenerating

```bash
python3 skills-pack/tools/export_training_jsonl.py
```

The script scans every `SKILL.md` under `skills-pack/`, so adding or editing a
skill automatically flows into the corpus on the next run.
